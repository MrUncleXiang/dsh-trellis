# 独立设计最终复核

复核对象：最新 `prd.md`（60 行）、`design.md`（120 行）与 `review.md` 的相关修正记录。结论只判断这份待批准方案草稿是否可交付批准；不代表功能已实现、宿主已接入或真实环境已验收。

## 初审 5 条及最终复核

1. **共用核心入口：初审不通过，最终复核通过。**
   - 初审：旧版把 DSH 内部模块直接当成共用核心，但没有宿主无关接口和稳定公开导出，Codex 无法真正复用。
   - 复核：`design.md:22` 承认绝对路径导入只能实测模块存在，尚未形成稳定公开导出；`design.md:23-30` 计划新增 `lib/core/index.js` 与 `./core` 导出，定义纯 JSON 接口、文件系统/会话/锁/时钟适配边界，并要求核心不依赖 DSH 库。`design.md:35-44` 让 DSH 与 Codex 两个入口调用该边界。原问题已消除。

2. **人工批准与任务状态：初审不通过，最终复核通过。**
   - 初审：旧版没有可信批准来源，且使用不存在的 `status=approved`。
   - 复核：`design.md:3` 只把 `draft`（草稿）表示文档自身状态；`design.md:80-81` 要求批准来自可信宿主用户事件，普通更新不能创建或修改，任务仍从合法的 `planning` 转 `in_progress`；`design.md:115` 把可信事件可获取性列为实施前置条件，无法取得时由用户选择手动确认通道。方案不再声称加适配器就能独立证明批准。原问题已消除，真实事件留待实施验收。

3. **跨进程锁释放与禁删冲突：初审不通过，最终复核通过。**
   - 初审：旧版没有锁释放和版本核对规则，直接删除锁会违反禁物理删除要求。
   - 复核：`design.md:88-92` 规定原子 `mkdir`（创建目录）获取锁、原子 `rename`（重命名）移入回收目录释放，明确等待超时、`ELOCKED`（锁超时错误）、租约核对、锁前后内容指纹比较和多锁顺序；任务、指针、产物、归档、批准均经同一核心接口写入（`design.md:84`）。原问题已消除。

4. **同步与回退命令：初审不通过，最终复核通过。**
   - 初审：旧版缺少完整同步命令，错误地用普通 `git revert` 处理合并提交，并用分离头指针回退。
   - 复核：`design.md:56-61` 给出无 `--prune`（清除远端旧引用）的 `fetch`（拉取）、`main` 的仅快进合并、维护分支合并顺序；`design.md:65-71` 规定合并提交使用 `git revert -m 1 <merge-commit>`、普通提交逐个回退，优先重新部署已验证维护版，不修改共享历史，并把项目数据单独备份和恢复。原问题已消除。

5. **维护版本身份：初审不通过，最终复核通过。**
   - 初审：旧版只保留上游 `version`，无法区分本地维护构建，且 `.trellis-version` 路径有误。
   - 复核：`design.md:48-51` 将上游版本只用于溯源，另设本地构建标识与受控 manifest（清单），记录上游、维护提交或不可变标记、构建标识、技能指纹和任务格式版本；`.agents/skills/.trellis-version` 保存维护构建标识，升级不只比较上游版本。原问题已消除。

## 剩余非阻断校对项

- `design.md:97` 的“真批准必须来自宿主用户确认事件”仍比 `design.md:80、115` 的“可信事件不可获取时由用户选择手动确认通道”更绝对。当前三段合读已能理解，不阻断；实施设计时应统一措辞，避免后续误以为只能使用一种通道。
